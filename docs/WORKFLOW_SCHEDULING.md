# 大任务协作调度：本地候选 rc.4 / Codex 包装 0.7.0

本轮在单任务执行链路之上增加持久化父任务和有向无环依赖图。Codex调用方做一次必要规划，DSH会话承担执行，程序负责依赖、并发、等待、停止与集成。源码候选尚未部署到当前运行环境或作为稳定版发布，不能称为已经复刻Codex Ultra内部算法，实际模型费用、完整长调用、DSH原生会话和工作台视觉仍待真机验收。

## 使用方式

简单或强耦合任务继续使用 `dsh_task_submit`。确实值得独立分工的大任务使用 `dsh_task_orchestrate`：

```json
{
  "goal": "完成两个独立模块；遵守原项目规范，不安装依赖，不提交Git",
  "cwd": "<ABSOLUTE_GIT_REPOSITORY_ROOT>",
  "idempotencyKey": "feature-workflow-001",
  "timeoutMs": 1800000,
  "parallelism": 2,
  "maxRepairs": 1,
  "maxModelCalls": 40,
  "review": false,
  "nodes": [
    {"id":"contract","goal":"明确双方接口并写入接口说明","writePaths":["docs/contract.md"]},
    {"id":"backend","goal":"按接口说明实现后端模块","dependsOn":["contract"],"writePaths":["server/feature"]},
    {"id":"frontend","goal":"按接口说明实现前端模块","dependsOn":["contract"],"writePaths":["web/feature"]},
    {"id":"integration","goal":"核对两模块接入，补充集成记录","dependsOn":["backend","frontend"],"writePaths":["docs/integration.md"]}
  ]
}
```

返回持久化父 `taskId/activeRunId`。后续 `dsh_task_await/get/answer/cancel/reconcile` 均可使用父编号；等待和查询不会另行调用模型。`WAITING_INPUT`使用父activeRunId与当前问题requestId，服务端转交当前子会话。原生审批仍由用户在对应DSH会话处理。

目标与必要共同要求会传给每个节点，只传该节点的计划、验收条件和有限依赖结果摘要，不复制主会话或全图历史。单节点组合上下文沿用20000字符限制，并预留依赖摘要空间。调用方仍需把节点目标写成自包含说明。

## 计划与准入

- 单层图1至12个节点，id唯一，依赖存在且无环；不允许节点递归提交子图或指定任意外部cwd。
- writePaths为明确仓库相对文件或目录，按目录前缀匹配，不支持通配符、越界、Git元数据、设备名或歧义路径。空数组表示只读交付。
- 无先后依赖的节点，声明的修改范围必须互不重叠。同一文件的连续修改可以用依赖关系排序。
- 整个任务与每个节点仍通过当前用户模型政策。服务端不扩张权限、不切换未授权模型、不把DeepSeek档位改称ultra。执行会话禁止反向调用Codex参谋。
- 父任务与普通任务按真实目录及父子目录互斥。同一原项目协作期间，后续普通写任务继续排队；工作区不同不代表可以绕过原项目所有权。

同一幂等键同内容返回原父任务；不同计划冲突。节点接纳与修复均先持久化意图，再用稳定幂等键进入原Task/Run执行器。调用方丢失响应时不新建图重跑。

## 隔离、依赖产物与统一集成

父任务启动时对原项目的已跟踪文件和未忽略的未跟踪文件生成有界快照，包含现有未提交修改，不创建源项目提交。每个文件最大10MiB，整个输入快照最大256MiB；符号链接、目录联接和子模块不作为普通文件复制。

节点工作区位于用户目录 `.dsh/codex-bridge/workflows-v1/<workflow-id>/worktrees/<node-id>`。使用真实独立Git worktree和独立索引，默认不执行checkout hook或smudge流程；工作文件由已校验快照写入。未复制node_modules、构建缓存等忽略文件，构建环境需项目自行准备，不会偷偷安装依赖。

后继工作区在原始快照上依次应用所有祖先的已捕获产物。只有节点执行结束、指定验证配置通过（如有）且文件差异在声明范围内，才释放依赖。没有验证配置的完成明确记录为未验证，不自动变成验收通过。

所有节点完成后统一按依赖顺序组成最终文件集。对原项目HEAD、目标文件初始哈希和权限做预检，每次替换前再次比较。期间用户修改了同一文件则进入RECONCILING，保留用户内容；不自动解决文本冲突，不强制覆盖。无关文件的修改保留。

集成写入前保存清单和原始内容，替换单个文件采用临时文件写入、同步和重命名。中断后对账可以识别已应用的文件；取消未完成集成时只回滚仍然匹配本次前后版本的修改。停止事实未知时仍待对账；所有执行者已确认停止后，若文件又被用户编辑或HEAD改变，取消会保留现有文件并明确记录rollbackIncomplete，不能冒充回滚成功或继续强行覆盖。全部写入已经完成的事实不会被改标成“从未执行”。

范围检查发生在交付时，工作区隔离不等于操作系统沙箱。DSH原有权限和审批仍然有效；拥有完全权限的进程并不因writePaths获得新的系统级限制。Git worktree也共享原仓库对象和部分元数据，执行者不得自行修改这些共享信息。

## 并发与预算

默认父并发2，允许1或2；执行器全局也最多两个DSH工作任务，普通任务与协作节点共用该上限。没有依赖关系才并行，不为增加Agent数而拆分。

父总时限默认30分钟，受现有配置上限约束，硬上限2小时；包括排队、快照、工作区准备、用户等待、执行、集成和验收。节点deadline不超过父deadline，修复不会重置父时限。协作总时限使用显式值或配置默认值，不采用历史自动延时。

maxRepairs是全图修复总数，默认1，允许0至2。节点失败时停止新节点准入，已运行的独立节点可完成；不会自动调用Codex或无限自修复。修复使用 `dsh_task_repair_node`：

```json
{"taskId":"workflow-...","nodeId":"backend","idempotencyKey":"repair-backend-001","goal":"仅修复已定位的接口字段不一致，保留已完成修改"}
```

修复保留原工作区和会话，重新声明总体要求和修改范围。普通retry和旧session复用入口不能绕过父预算。源文件冲突由对账处理，不能借节点修复放宽原修改范围。

maxModelCalls默认40，是整个父任务下所有DSH运行（含失败和修复）的**已观测**模型调用数上限。可选maxObservedTokens对已观测的未缓存输入、缓存读取/写入和输出计数求和。未知指标不补零冒充完整用量，也不会抹掉其他节点已经观测到的消耗。

每个Run另存已观测预算下界；历史分页不全或重启对账返回更小窗口时，不减少已经确认的消耗。新回答阶段只追加新事件，修复历史也保留在父预算中。下界计数与完整账单展示明确分开，不能把未知缓存或费用当成已知零。

观测预算在真实usage事件返回后生效：可以停止后续派发、请求停止活跃节点，但在途请求可能超出阈值，不是服务商计费硬限额。调用方Codex规划/协调用量未知；没有可靠价格就不推算费用。

review=true只在集成后调用一次桥内Codex审查，不对每个节点重复审查。审查调用先记录意图；重启时上次审查结果未知则保留unavailable，不自动再付费调用来猜测结果。

## 等待、恢复与维护

WORKFLOW_PAUSED为可处理状态，父await返回失败节点和issue；RECONCILING保留所有权，不能假定已停止。原生提问、审批和未知停止事实都不会通过重新提交来绕过。

重启后非终结父任务进入RECONCILING。明确对账后，已派发节点只观察绑定会话，不重新执行；未接纳节点才可按已保存计划继续。已知未派发的队列可以恢复，原deadline保持。准备中断且缺少完整工作区证据时保留现场，不能靠删除目录盲目重建。

维护begin关闭新图、新独立任务和新修复准入，已接纳图的剩余计划节点仍可排空。父子任务或工作区操作尚未结束时ready=false；不要通过取消任务来腾空升级。

工作台显示父子依赖、阶段、节点范围、失败原因和全图修复次数，可打开对应原生会话、回答当前问题或修复指定节点。列表默认显示父任务和独立任务，子任务从父详情进入。前端按程序轮询，不让模型盯普通进度。

创建协作计划目前使用Codex的orchestrate工具入口；工作台保留原单任务新建表单，协作详情用于查看和操作已提交的图。

工作区及内容快照会保留以便审计，没有自动删除。现有task-data日志备份工具遇到协作记录会明确拒绝不完整备份/恢复；尚未提供可移植的一键协作备份。需要离线共同保留tasks-v2、workflows-v1以及原仓库和Git worktree注册元数据，路径关系保持；单独恢复日志不能保证恢复执行现场。
